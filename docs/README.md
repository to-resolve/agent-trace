# agent-trace · 指挥文档

本目录由**架构负责人**维护，AI 编程 Agent 在此读取指令并实施。

## 项目一句话

**多 Agent 因果可追溯控制台** —— 现有 Agent 可观测性工具只能回答"发生了什么"（时间线），本项目回答"什么导致了什么"（provenance 有向图 + 双向溯源 + 时间旅行）。

类比：它是 Agent 领域的 Vue DevTools / Chrome Memory 面板——别人做的是 Network 瀑布图，我们做的是依赖引用关系图。

## 协作模式：增量推进

**本项目不预先规划全部任务。** 推进节奏是：

```
发布一批任务卡 → 执行者实现 → 架构负责人审查代码 → 调整后续计划 → 发布下一批
```

任务卡**逐批发布**，每批完成后审查一次。原因很直接：前序实现必然暴露设计时未预料的问题，提前把计划写死等于逼着后面将错就错。审查结论可能回头修订 `01` / `02` 文档。

因此：**执行者只做 `03-任务看板.md` 中已展开细节的卡**，不要根据批次方向自行提前开工。

## 执行者工作流程

1. 读 `03-任务看板.md`，找到状态为 `todo` 且已展开细节的任务卡
2. 按该卡的「目标 / 输入 / 输出 / 验收标准 / 禁止事项」执行
3. **只做当前卡范围内的事**，不提前实现后续内容
4. 完成后在 `docs/submissions/T{n}-提交.md` 提交材料，并把任务卡状态改为 `submitted`（不要改 `done`）
5. 有歧义**不要自行决策**，在卡下标注 `BLOCKER` 等待裁决

## 铁律

- **核心层零框架依赖**：`src/core/`、`src/render/` 不得 import 任何 React 相关内容。违反即退回重做。
- **不引第三方图布局库**（dagre / elkjs / d3-force / cytoscape / reactflow）。分层布局自研，这是项目主要技术亮点。
- **不引 AG-UI 官方 SDK**（`@ag-ui/*`）。协议解析层自研，控制在 300 行内。
- **禁止超出当前任务卡范围做事**。宁可少做，不可多做。
- **禁止用 `any` / `@ts-ignore` / 类型强转绕过设计问题**。类型报错说明设计有问题，提出来。
- 任何新增依赖须先登记到 `01` 的依赖白名单，未登记不得安装。
