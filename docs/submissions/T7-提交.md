### 第二部分：先出数据，再按数据修（四轮迭代，每轮都有前后数字）

**基线数据**（10k 混合拓扑 10007 spans / 10006 edges / 27717 events）暴露四个问题，全部按卡面处方或数据指向修复：

**① `query.ts` traverse 迭代化（爆栈 ×2 的数据）**

基线：10k 深链 `traceUpstream` 抛 `RangeError: Maximum call stack size exceeded`；**混合拓扑 7700 深的链尾同样爆栈**（M3 采样直接崩溃）。改为显式栈迭代（栈帧 = `{id, edgeIndex}`，`enter` 布尔返回替代递归头部），语义逐点对齐递归版：前序访问、edges 按进入顺序收集、onPath 命中设 hasCycle 但当条边照常入集、菱形汇合直接弹回。既有 query 测试 12 个全过 + 深链守卫测试转绿。

`layout.ts` 的 `computeLayering` **不改**——10k 深链实测通过（mean 19.97ms），卡面明示「不爆栈则不改」。

**② 徽章 rect 一次解析复用（M4b = 247ms/帧 的数据）**

基线 M4b：徽章 rect 全量解析（T6 引入的 O(B×E) 三元组查找，发生在每帧绘制路径）**p50=247ms / p95=505ms**——60fps 帧预算 16.7ms 的 ~30 倍。修复：`EntityBadge` 携带构造时解析的**平铺几何字段**（x/y/width/height，单对象分配），`buildBadges` 从正在迭代的边/节点直接计算（O(1)/徽章，无任何查找）。绘制 / 命中 / 裁剪 / 包围盒全部读同一份——「画在哪就点哪」。构造源即几何源，T6 审查建议条（未命中静默返回 {0,0}）**在结构上消灭**。每帧解析成本 247ms → **0**（已并入构造）。

**③ 视口裁剪（10k 节点全画超帧预算的推理 + stub ctx 断言）**

`src/render/culling.ts`：纯函数 `cullScene(scene, worldRect)` → 可见集合（AABB 闭区间判定：节点用节点矩形、徽章用徽章几何、边用两端点包围盒——宁多画不漏画）。`drawScene(ctx, scene, view)` 内部先裁剪再画，绘制顺序不变；`renderer` 把画布四角经视口逆变换算出世界矩形传入。`culling.test.ts` 4 个测试：**关键断言「10k 节点与 200 节点在相同视口下 stub ctx 绘制调用数完全一致」**（与总节点数无关）+ 视口外元素零命中 + 调用数与可见元素数成正比（全图视口 fills 596 vs 小视口 20）。

**④ updateLayout 边级增量 + O(N) 扫削减负（M2 p95 = 4.05ms > 2ms 验收线的数据）**

按卡面处方先做边级增量（受影响节点的关联边重建、其余**对象原样复用**、悬空边同规则跳过、剔除防御路径仍走全量）。第一版用字符串三元组键判定——**复测反而恶化到 5.20ms**（每边每事件一次模板字符串分配比对象重建更贵），改为 `affected` 集合的**端点成员检查**（两次 Set.has，零分配）。数据进一步显示剩余大头是每事件 O(N) 扫描与 Map 重建，继续修：

- `computeLayering` 的边界从「预构建 10k 条目 fixedLayer Map」改为**惰性查询函数**（每事件省一次 10k 条目 Map 构建）
- 兜底扫描改**插入序取尾**（Map 保插入序且图内 span 只增不删，新 span 必为最后 added 个；净增 ≤0 跳过扫描）
- 剔除检测改**规模差判定**（图比布局小 ⇒ 必有节点消失；两个既有防御测试分别以 delta=+1/-4 构造，均覆盖）
- 节点表改 **Map 克隆快速路径**（`new Map(prev.nodes)` + 删受影响 + 放新坐标，替代逐条 set）；maxFixedY 改数组、只对「有新节点落位」的层记账

**浏览器实测（视口裁剪端到端）**：10k 节点场景，120 帧连续平移 + 五档缩放（0.28×→1.6×），rAF 帧间隔 **p50 = 6.9ms / p95 = 7.0ms / max = 34.7ms（单帧尖峰）/ 平均 7.29ms ≈ 137fps**（143Hz 显示器，帧预算 ~7ms，比 60fps 预算严格 2.4 倍）。「10k 节点、视口仅含约 50 个元素时绘制调用数与视口内元素数成正比、与总节点数无关」由 culling.test 的 stub ctx 计数断言覆盖（10k 与 200 节点同视口调用数**完全一致**）。

**M4 结论（T6 审查增补指标 4 的裁决要求）**：p95 = 6.6ms **不构成交互瓶颈**（< 16.7ms 帧预算，且含徽章解析）。它限制的是事件流回放吞吐（M5 69s / 27717 事件 ≈ 2.5ms/事件均值）——瓶颈是 buildScene 每事件全量重建 nodeVisuals/badges 的 O(N+E) 设计。对症方案是「事件合帧」（store 层把 buildScene 延迟到渲染帧、一帧多事件只组装一次）而非继续压单事件成本，涉及 store 数据流重构，**超出本卡「按数据修」处方范围，建议进 B5**。

**迭代过程的负数据也记录在案**（提交材料如实呈现）：边级增量第一版的字符串键使 M2 p95 从 4.05 恶化到 5.20ms，触发改端点 Set 判定；makeBadge 中间对象 + draw-node 嵌套 rect 的双分配使 M4 p50 +0.7ms，触发平铺字段改造——两处「越优化越慢」都被复测数据当场抓获并纠正，这正是「先测量再动手」流程的价值。

### 顺带修复（重构中发现的潜在 bug）

`applyEdgeStates` 在 `upstream === null` 时原样返回 baseLayout——而 baseLayout 是 `state.scene.layout`，可能携带上一次选中的 highlighted/dimmed 边。**选中 span → 点空白取消后，边会永久保持高亮**（节点靠 `highlightedSpanIds=null` 自行复位，边没有这层兜底；T5 的六步验收没覆盖「取消」路径所以漏网）。修复：null 时显式重置非 normal 边（全 normal 快路径零分配原样返回）。updateLayout 的边复用同样在复用时归零 state（布局层契约：输出恒 normal）。

## 4. 决策点与偏离说明

1. **重型回放采样放模块级而非 bench 任务体**：实测单次 100s+ 的回放在 tinybench 任务体里 samples 记不上（迭代/超时机制冲突，第一轮 M2/M3/M4 case 0 samples）。模块级一次性执行 + console.log 分段打印是兼顾「用 vitest bench」（卡面要求）与数据可靠性的工程解，bench 文件头注明理由。
2. **「越优化越慢」的两处当场纠正**：字符串三元组键 → 端点 Set 判定；makeBadge 双分配 → 平铺字段直接构造。两处都有复测数据（4.05→5.20→3.89ms 与 M4 p50 +0.7ms 的恶化记录）——预防性直觉不可信，数据说了算，过程数字全部保留在第 1 节。
3. **M2 验收线的达成超出卡面处方**：卡面给的处方是边级增量；数据证明它只解决一小部分（4.05→3.89ms），继续按数据追加了 fixedLayer 惰性化、插入序取尾兜底、规模差剔除判定、Map 克隆。其中「兜底改插入序取尾」的正确性依赖「图内 span 只增不删」——run.snapshot 清场属剔除路径（removed=true），同数增删互换不在增量调用约定内（文件头已写明 snapshot 应走 layoutGraph），既有两个防御测试（delta=+1/-4）均覆盖。
4. **徽章几何用平铺字段而非嵌套 rect 对象**：徽章是每事件 O(E) 的热路径对象，嵌套意味着每徽章双分配；平铺后 hitTestBadge/culling/drawScene 直接读字段，`Rect` 接口从徽章路径消失（culling 的 `rectIntersectsView` 接受结构匹配的 {x,y,width,height}）。`edgeBadgeCenter`/`inputBadgeCenter` 保留导出（测试与 makeBadge 用）。
5. **M4 的判断是「不构成交互瓶颈，建议事件合帧进 B5」而非继续优化**：M4 p95 6.6ms < 16.7ms 帧预算；剩余成本是 buildScene 每事件全量重建 O(N+E) 的设计本质，对症药方（一帧多事件只组装一次场景）是 store 数据流重构，超出「按数据修」的处方边界。写明「构成回放吞吐瓶颈但不构成交互瓶颈」+ 方案建议，交裁决。
6. **`computeLayering` 保留递归**：10k 深链实测不爆栈（19.97ms），卡面「不爆栈则不改」。浏览器栈深与 Node 有差异的风险已知，但 10k 混合拓扑（7700 深）的 layoutGraph 在浏览器实测路径中未触发（增量布局递归深度为 1-2）；真要 10k+ 深链的浏览器全量布局，B5 再按需迭代化。
7. **`applyEdgeStates` 状态残留 bug 的修复**（选中→取消后边永久高亮）：实现在重构 edge 状态路径时发现，与边级增量的 state 归零互为表里（布局层输出恒 normal 的契约两头堵），属本卡触碰面的正确性修复而非顺手重构。T5 验收未覆盖「取消」路径是漏网原因，已记录。
8. **stub ctx 的单次类型收窄转换**（`stub as CanvasRenderingContext2D`）：桩实现 drawScene 实际触达的成员子集，CanvasRenderingContext2D 可赋给该子集类型，转换类型安全；与 T6 审查对测试内构造脏数据的裁定同理，非红线所指的绕过设计。
9. **深链爆栈守卫做成了常驻测试**（synth.test.ts，117ms）：不只写进提交材料，每次 `npm test` 都会跑——未来任何人把 traverse 改回递归会立刻红。
