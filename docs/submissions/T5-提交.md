## 1. 实现记录

### render 层（零 React 依赖，只 import `core/types` 与本层模块）

- **`viewport.ts`** —— 视口纯函数：`screenToWorld` / `worldToScreen`（`screen = world * scale + offset`）、`zoomAt`（锚点缩放，锚下的世界点屏幕位置不动；factor=1 或夹在边界时原样返回避免浮点漂移）、`panBy`、`fitViewport`（留 40px 边距等比居中，空内容退化为 scale=1 防除零）、`clampScale`（[0.1, 2]）。DPR 不在本层——由 renderer 作为基线变换处理，视口只在 CSS 像素层面工作
- **`draw-node.ts`** —— 绘制与视图模型。`Scene`（version + layout + nodeVisuals + badges + highlightedSpanIds）由 store 组装喂入，渲染层不读 `CausalGraph`（02 §10）。要点：
  - **因果边徽章**锚在边中点，显示实体 `label`；`stale` 追加「· N 天」并变红（`badgeText`）
  - **外部输入徽章**（`producedBy === null`，按 02 §4 无因果边）：锚在消费者 span 左缘伸出的虚拟短边（`INPUT_STUB = 160`）中点，同 span 多个输入按 `slot` 垂直堆叠。**e-policy 是验收第 5 步的对照组，必须在图上可见可点**——这是它出现在图上的唯一途径
  - 外部输入徽章与因果边徽章同行必然水平重叠（徽章宽普遍超过层间距 80px），整体下移 `INPUT_BADGE_DROP = 26` 错开一行（如 s-decide 的 e-policy 与其进入边上的 e-score 徽章）
  - 绘制顺序：因果边 → 外部输入短边 → 节点 → **徽章最上层**（宽徽章画在节点下会被遮住大半，红色与天数就看不见了）
  - 绘制与命中测试**共用同一份**徽章几何（`badgeRect` + 常量），保证「画在哪就点哪」
- **`hit-test.ts`** —— AABB 命中纯函数，一律在世界坐标判定，调用方先经 `screenToWorld` 变回
- **`renderer.ts`** —— 绘制调度：`requestDraw` 只登记最新 (scene, viewport)，实际绘制延迟到 rAF，**一个帧间隙内无论 store 更新多少次都只画最后一次**（「禁止一个事件一次重绘」）；再叠加版本签名比对（scene.version / viewport / 画布尺寸全相同则跳过）。DPR 作为 `setTransform` 基线，业务绘制一律 CSS 像素。全量脏矩形分块重绘留给 T7 万级压测

### store 层

- **`traceStore.ts`** —— Zustand 唯一状态源。职责链：订阅 `SimulatedSource` → `applyEvent` 增量建图 → `updateLayout` 增量布局（dirty 约定按 `layout.ts` 文件头：`span.start` 标自身、`entity.create` 标 producedBy）→ `buildScene` 组装视图模型。要点：
  - `applyEdgeStates`：利用「graph.edges 过滤悬空边后与 layout.edges 一一对应」把 `traceUpstream` 的边集合映射成 LayoutEdge 视觉态（高亮/dimmed）
  - `selectSpan` → `traceUpstream` → 上游链高亮、其余 dimmed；点空白 `clearSelection` 取消
  - `selectEntity` **保留 span 高亮链**，只切换检查器内容（决策点 3）
  - `startRun` 里以 graph 引用比对丢弃被新 run 取代的迟到事件
  - `FRESHNESS_THRESHOLD_MS = 7 天` 在本层导出——阈值是查询参数不是数据属性（02 §3），B4+ 再做可配置
  - 事件源与运行句柄是模块级单例，不进 React 状态

### ui 层（只做状态绑定与事件转发）

- **`ScenarioList.tsx`** —— 左栏剧本列表 + 播放入口
- **`GraphCanvas.tsx`** —— Canvas 容器：wheel 缩放（`passive: false` 才能 preventDefault，React 合成事件做不到，故用原生监听）、拖拽平移（`CLICK_SLOP = 4px` 区分平移与点击）、点击选中（**徽章先于节点**判定，与视觉层级一致）、ResizeObserver 尺寸自适应、图生长期间自动适配（决策点 4）
- **`NodeInspector.tsx`** —— 右栏：选中实体显示 `payload` / 产生时间 / 读取时间 / `source` / 数据年龄徽章（红「91 天 · 已过期」）；选中 span 显示执行详情与输入/输出实体 chips（chip 可点 → 选中该实体）
- **`App.tsx`** —— 三栏布局 + 顶栏（运行状态与暂停/继续/取消）

## 4. 决策点与偏离说明

1. **外部输入实体（`producedBy === null`）的图上呈现**：02 §4 规定它们不产生因果边，但 e-policy 是验收第 5 步的对照组、e-query 是溯源链的根，图上必须可见可点。方案：徽章锚在「消费者 span 左缘伸出的虚拟短边」中点（虚线绘制，与实线因果边区分），同 span 多个输入垂直 slot 堆叠。短边是纯视觉锚点，不进图模型、不影响 layout——渲染层自己的几何。
2. **徽章绘制在节点之上、命中判定徽章优先**：徽章宽（stale 追加「· N 天」后 180px+）普遍超过层间距 80px，若画在节点下面会被端点节点遮住大半，红色与天数不可见。04 §4 的徽章是视觉焦点，压在节点边缘上是特性。命中顺序与视觉层级一致——点到看到的东西。
3. **`selectEntity` 保留 span 高亮链**：任务卡未规定选中实体与选中 span 互斥。点击徽章查实体详情时若清掉链高亮，用户得重新点节点才能恢复溯源上下文，违背「3 秒定位」的产品目标。实现上只切换 `selectedEntityId` 并自增 scene.version，`selectedSpanId` 不动。
4. **图生长期间的自动适配**：首个节点 fitViewport 会顶到 MAX_SCALE=2，后续节点很快长出画布外（决策节点与徽章不可见）。因此在用户手动缩放/平移之前，每次节点数变化都重新适配，让「逐步生长」全程在视野内；用户一动镜头（滚轮或拖拽超 CLICK_SLOP）即永久交还控制权，重开 run 时恢复自动。任务卡未规定此行为，属产品可用性决策。
5. **渲染层未 import T4 导出的布局尺寸常量**：`LayoutNode` 契约已携带全部几何（x/y/width/height），渲染只需读数据无需常量；且 01 §4 规定 render/ 只依赖 `core/types.ts`，import `core/graph/layout.ts` 会违反分层红线（该规则的优先级高于 T4 卡「常量供 T5 复用」的建议性表述）。两者实际不冲突：几何由布局产物传递，无需常量耦合。
6. **store → render 的类型引用**：`traceStore.ts` 以 `import type` 引用 `Scene` / `EntityBadge` / `NodeVisual`。01 §4 依赖图 `ui/ ──→ store/ ──→ core/` 与 `└──────────┴──→ render/` 中 store → render 箭头成立，非反向依赖；纯类型导入无运行时耦合。
7. **徽章几何常量（INPUT_STUB / INPUT_BADGE_DROP / BADGE_* 等）定义在 draw-node.ts 并导出**：绘制与命中测试必须共用同一份（画的是同一个矩形），这是「画在哪就点哪」的保障，也是徽章可点性（验收⑥）的实现基础。
8. **`index.css` 为本卡新增**：T1 骨架只建了 tailwind.config.js / postcss.config.js，未建指令文件。三栏布局依赖 Tailwind 工具类，缺它则 `h-screen` / `flex` 等全部失效（开发中实际踩到：画布高度失控、三栏纵向堆叠）。
9. **手动验证的取证手段**：六步现象均来自真实浏览器操作（合成 PointerEvent 点击画布、`getImageData` 像素扫描、DOM 文本读取），非目测描述。其中「逐步生长」用节点填充色连通域计数而非边框色检测——边框 1.5px 世界宽在 0.4x 缩放下无纯色像素（抗锯齿混合），填充色是大面积纯色可稳定检出。
