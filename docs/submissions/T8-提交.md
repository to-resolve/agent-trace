## 4. 决策点与偏离说明

1. **B2 第一项放在新建的 `src/store/scene.test.ts` 而非塞进现有文件**：`store/scene.ts` 自 T7 抽出起就没有配套测试（01 §5 要求「core/ 下每个模块必须配 .test.ts」——严格说 scene.ts 在 store/，白名单无硬性要求，但同一精神）。三项验证里它是最纯粹的场景组装行为测试，归属 scene 正确；也顺带补上模块欠账。
2. **未装 @types/node**：bench 环境指纹需要 `node:os` / `process` 类型，但 @types/node 不在依赖白名单（01 §2 未登记禁装）。改用 `src/bench/env.d.ts` 本地最小声明（只声明用到的 4 个函数 + 2 个字段），零新依赖——与 T6 审查对测试内 stub 的裁定同理。
3. **A 组口径选择「回放全程分布 + 只报 p95/p99」而非改测满图单事件**：改善率要与 T7 优化前基线（4.05ms，回放口径）同口径可比——改成满图口径就没有基线可比了。卡面给了两个选项，选可比性优先；同时新增 **B 组满图单事件口径**（批量计时）作为对「计时开销占比」缺陷的正向回应，两组并存、口径各自声明。
4. **B 组的图规模漂移（12k→18k）如实呈现而非消除**：每轮重置图需完整回放（+30s/轮），且「追加型事件」天然改图。轮间数字渐升（2.3→4.5ms）是 O(N) 成分的真实体现，方向保守不虚报；已在 bench 输出与提交材料双处声明。若审查需要消除漂移的版本，可用「每轮重建图」实现，成本是 bench 总时长翻倍。
5. **`coverage-verify/` 的处理**：首次 `git add -A` 时发现被捡入（T7 审查独立复现的产物）。选择「移出暂存 + .gitignore」而非删除目录——是指挥者的文件，磁盘保留可随时复查，只是不进版本库。此处理在变更清单 git 节明确记录。
6. **engines 写 `>=22` 而非固定单版本**：卡面说「声明推荐 Node 版本」。Node 22/24 双版本实测均正常工作（数字见上），写 `>=22` 表达「22 起可用」，推荐 24（性能更优：全指标 ~25%）写进提交材料而非 package.json（避免过度限制未来环境）。
7. **M3 的 4.29ms（Node 24）vs T7 提交材料 6.76ms**：同代码不同数字——T7 的 6.76ms 是无预热单轮，本次为预热后多轮中位（JIT 稳态）。这正是方法学修正的直接体现，非代码变化。
8. **10k 一致性测试使 `npm test` 增至 13.5s**：主因是 11.4s 的 10k 回放。可拆成仅 CI 跑的独立标记，但卡面要求「正式测试套件内有 10k 规模覆盖」，且 13.5s 仍在可接受区间——不引入测试拆分复杂度。
