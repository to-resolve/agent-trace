### 关键实现决策

1. **剧本相对时间的换算口径**：`docs/04` 只显式定义了 `timeOffset` 的换算，但剧本 JSON 里 `run.start.startedAt`、`span.startedAt/endedAt`、`run.end.endedAt` 也全是相对 run 起点的偏移（0/200/900…）。统一处理为「剧本中一切 number 时间字段都是相对偏移，`resolveEvent` 一律加 `runStartedAt`」。
2. **`observedAt` 省略时取「计划发生时刻」而非 fire 时刻的墙上时钟**：计划时刻 = `runStartedAt + 累计 delay`，在 `start()` 时预计算。结果只依赖剧本与基准，不受定时器抖动影响，测试断言因此确定。
3. **`loadSnapshot` 以内存归档实现**：`start()` 时为每个 runId 建 `RunArchive`，事件吐出时顺带归档（`span.end` 合并进对应 span 的 `status/endedAt/outputEntityIds/error`），`loadSnapshot` 查归档返回。SimulatedSource 因此接口完整、可回查，且不引入持久化。
4. **`cancel()` 不触发 `onDone`/`onError`**：二者专属「自然结束」与「出错」；主动取消方自知已取消。`pause` 后的 `resume` 与 `cancel` 后的状态互斥（4 态状态机 running/paused/done/cancelled）。

## 4. 决策点与偏离说明

1. **`docs/02` 第 9 节与 `docs/04` 的契约偏差（请裁决是否回头修订 02）**：02 第 9 节定义 `Scenario.steps[].event: AgentEvent`，但 04 的剧本 JSON 中 `entity.create` 的实体用 `timeOffset`（相对偏移）而非 `time`（绝对时间），且 `run.start/span.*` 的时间字段同样是相对偏移。按 T2 卡指定输入 04 落地：代码中 `ScenarioEvent` 为「相对时间形式」的剧本事件类型（`entity.create` 的 time 换为 timeOffset，并排除 run.snapshot——回放语义不应出现在剧本里）。02 第 9 节的 `Scenario` 若按字面落地则装不下 04 的剧本，请架构负责人确认修订 02。
2. **`resolveEvent` / `ScenarioEvent` 导出位置**：放在 scenario.ts（时间换算是剧本加载职责的一部分），simulated.ts 消费。02 未指定该内部函数归属。
3. **tsconfig 增加 `resolveJsonModule: true`**：任务卡输出清单未列 tsconfig 修改，但测试 import 剧本 JSON 必需此选项，属实现必需的最小变更。
4. **`loadSnapshot` 语义**：任务卡未规定 SimulatedSource 的 loadSnapshot 行为，采用内存归档（见实现记录 3）；同 runId 重复运行会覆盖旧归档（剧本 runId 写死为 `run-stale-demo`，重复 start 即覆盖）。未做持久化——那是 ReplaySource（Phase 1）的职责。
5. **`pause()` 的剩余毫秒计算**：`armTimer` 时记录 `plannedFireAt`，pause 时 `remaining = plannedFireAt - now`，resume 按剩余值重排。delayMs=0 连发场景下 remaining 可为 0，行为正确。
6. **测试对 `onError` 的处理**：测试中 `onError` 直接 throw（模拟源正常路径不应报错，报错即失败暴露），未单独构造错误注入场景——本卡的验收标准不含错误传播路径。
