## 4. 决策点与偏离说明

1. **snapshot 既有测试的修正方式**：runId 冲突抛错后，`build.test.ts` 的 snapshot 测试红——它建图用 `run-test`、快照用 `run-snap`。裁决预警「若因此导致既有测试失败，说明有测试在跨 run 复用图实例，提 BLOCKER」。判断：这是**测试 setup 瑕疵**（该测试意图是验证清空重放语义，runId 随手写了不同值；产品侧 traceStore 每次 startRun 建新图，无跨 run 复用），故修测试（同一 runId）而非提 BLOCKER。若审查认为此判断越权，可改走 BLOCKER 流程。
2. **journal 记录的实现形态**：`Recorder = ((op) => void) | null` 贯穿五个写入点。备选是「journal 判定内联在每个写入点」（`if (journal) ...`），但会让写入语义代码与记录代码交错难读；Recorder 把记录收敛为一次函数调用，null 时分支预测友好。代价是闭包每事件创建一次（实测 M2 退化 4.8% 含此成本）。
3. **`adj.truncate` 记录时机的一个细节**：addEdge 的逆操作在写入前记录三处截断长度（edges / out / inc）。`out`/`inc` 不存在时记 length 0（还原 = delete 键）——与「硬约束 length 0 必须删键」配套。测试专有一条覆盖「多出边/多入边节点非零长度截断」。
4. **journal 测试的 snapshot 教训**：`snapshot()` 辅助函数首版捕获 `edges: graph.edges`（数组引用）——基准图持续生长污染了先拍的快照，回滚断言对着终态比（红）。修复为复制数组（span/entity 对象因替换式写入引用安全）。这个坑本身就是「替换 vs mutate」重要性的又一实证：**引用被共享时，快照与回滚互相污染**。已写进 snapshot 函数注释。
5. **压力回滚测试用 400 节点而非 10k**：10k 回放 ~73s×2（基准+回滚）会把单测拖到分钟级；400 节点已覆盖同一断言形态（随机 4 检查点逐字段相等），10k 规模的回滚正确性由第二部分 checkpoint 测试承担（其验收本就要求 10k）。
6. **bench 的 A 组附只跑单轮**：journal 开启的对比是「同轮环境同代码路径」的差值测量，单轮已能给 4-5% 的稳定差值（M2/M4/M5 三指标一致）；多轮中位数对差值测量增益有限，且每轮 +75s。若审查需要多轮形态，可并入下一部分跑。

2. **回退统一走 invert 而非 checkpoint 重放**（审查 4.3 授权的偏离）：invert 单组微秒级且无需 clone，任何距离都快于「checkpoint 深拷贝 + 正向重放」；checkpoint 的角色转为①前进大跳的跳板（唯一能跳到未来的路径）②fork 的起点（第三部分）。§11.5 的「checkpoint + 重放」算法保留在「回退越过 journalBase」与「大步前进」两条路径上
