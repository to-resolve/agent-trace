## 4. 决策点与偏离说明

1. **`BadgeAnchor` edge 变体的具体形状**：卡面说「具体形状自定，但必须消灭 edgeIndex」。取 `{ fromSpanId, toSpanId, viaEntityId }` 三元组——`(from, to)` 对不能唯一确定边（同一对 span 间可经不同实体有多条因果边，`build.ts` 的 `addEdge` 以三元组判重），必须带上 `viaEntityId`。`badgeCenter` 按三元组在 `layout.edges` 线性查找（当前规模 E≤4 无感；若 T7 压测显示徽章解析成为 10k 瓶颈，届时按数据再换索引，不在本卡预优化）
2. **`hit-test.test.ts` 新增一个测试**（超出「如有测试依赖 edgeIndex 一并改」的字面）：构造 `layout.edges` 顺序与徽章顺序故意相反的场景，断言徽章仍按标识命中正确边。这是「下标耦合已消灭」的最直接回归证明——没有它，未来有人把 `badgeCenter` 的 find 改回按序取值也不会有测试红。一行场景换来契约保障，值得。
3. **`applyEdgeStates` 删除 `graph` 参数**：标识化后不再需要走 `graph.edges` 对齐，签名收缩是耦合消灭的自然结果而非顺手重构。
4. **注册表放 `src/core/source/registry.ts`**：`import.meta.glob` 是 Vite 构建期转译能力（vitest 同走 Vite 管道），非运行时框架依赖，不触碰「core 不得 import React / 上层」红线。放 core/source 让测试与 store 共用同一入口。
5. **测试经 `loadScenarioById` + top-level await 获取剧本**：四个测试文件各一行模块级 `const staleContext = await loadScenarioById('stale-context')`。预先用 `rg` 核实了全部测试不突变 scenario 对象（共享单实例安全）；`simulated.test.ts` 手构非法 JSON 的校验器直测不受影响。
6. **`init()` 的防重入用模块级 `initStarted` 标记**而非旧的「set 后查 scenarios.length」：装配改为异步后，StrictMode 下 effect 双调用会在列表 set 之前双双发起加载（旧守卫在异步世界里失效），标记位保证只加载一次。装配失败上屏 `runError`（header 已有红字呈现位），不静默吞。
7. **`startRun` 的双守卫**（runId 命中 + `source` 非空）：装配完成前列表为空、按钮不存在，第二个守卫实际不可达，是 TS 对可空模块级单例的类型收窄需要，两个 early return 语义诚实（未装配完成 = 无可运行之物）。
8. **补了 `registry.test.ts`（3 个测试）**：`01` §5 要求 core/ 下每个模块必须配 `.test.ts`，新建模块不配即违规。覆盖加载/按 id 取件/未命中抛错三路径。
9. **`layout.ts` 的过时注释一并修正**：该注释描述的「契约不带端点」在 §10 修订后成为错误陈述，留着会误导 T7 的执行者；改成如实记录「边级增量可行、留 T7 按数据裁决」。属契约修订的同步落地，非顺手重构。
