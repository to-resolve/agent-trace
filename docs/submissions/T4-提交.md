## 1. 实现记录

新增 `src/core/graph/layout.ts`，两个入口的语义严格按任务卡成立：

### 全量布局 `layoutGraph(graph: CausalGraph): Layout`

- **分层（最长路径法）**：`computeLayering`（`layout.ts:61-97`）按 `layer(span) = max(layer(上游)) + 1` 递归，无上游者为 0。备忘录 `layers` 区分「已算完」与「路径上」，菱形汇合（A→B→D、A→C→D）不算环不重复递归
- **环打破**：DFS 的 `onPath` 集合上出现过的入边来源 → 该边记为回边（`layout.ts:84-87`），不参与层级约束与重心计算但**仍渲染**。判定语义与 `query.ts` 的 `hasCycle` 一致（`02` §5 的环测试事件流直接复用）
- **层内排序（重心法）**：`orderLayers`（`layout.ts:107-166`），初始顺序 = span 入图顺序，之后固定 `BARYCENTER_SWEEPS = 4` 轮「下扫-上扫」交替：下扫按上游邻居层内序号均值重排本层，上扫按下游邻居均值重排。无邻居节点保持当前位次；排序稳定可复现；只用约束边（非回边、两端在图内）计算重心
- **几何**：自左向右。节点左边缘 `x = layer * (NODE_WIDTH + LAYER_GAP)`，同层第 k 个节点上边缘 `y = k * (NODE_HEIGHT + NODE_GAP)`（`makeNode`，`layout.ts:191-200`）。尺寸常量 `NODE_WIDTH` / `NODE_HEIGHT` / `LAYER_GAP` / `NODE_GAP` 全部具名导出，**供 T5 渲染层复用同一份**（任务卡硬要求）
- **边几何**（`buildEdges`，`layout.ts:175-189`）：起点 = 源节点右缘中点，终点 = 目标节点左缘中点；端点不在图内的悬空边跳过；`state` 恒为 `'normal'` —— 高亮/置灰是交互状态，归渲染层与 store，布局层只负责几何
- **bounds**：恰好覆盖全部节点范围（width = max(x+width)，height = max(y+height)）；空图为 `{0, 0}`，`version` 从 1 起

### 增量布局 `updateLayout(prev, graph, dirtySpanIds): Layout`

按 7 步流水（`layout.ts:225-333`）：

1. **受影响集合 = dirty ∪ 新节点（兜底）∪ 沿出边的下游闭包**。兜底指「图里有、prev 里没有的 span」自动并入（防御调用方漏标 dirty），是一次 O(V) 成员扫描，**不触发全量重排**
2. **节点剔除检测**：prev 里有、图里已不存在的 span（如 run.snapshot 清场后误用增量）→ 走重建
3. **无变更原样返回 prev 本身**（引用相等，version 不自增）—— 渲染层可据此跳过重绘
4. **增量分层**：不受影响节点的 prev 层号作为已知边界（`fixedLayer`）传入 `computeLayering`，直接引用不递归。环必然整体落在受影响集合内（环上任一节点 dirty 时，下游闭包会把整条环收进来），边界入边不可能是回边，层号引用安全
5. **组装**：不受影响节点**直接复用原 `LayoutNode` 对象**（逐字段不动的最强形式）；受影响节点按新层分组、层号升序处理，层内顺序用增量版重心 = 上游（固定节点或已落位节点）y 中心的均值，无上游邻居保持入图顺序；新节点排在同层固定节点下方（`maxFixedY + Y_STRIDE` 起步），保证同层不重叠
6. **边 O(E) 重建**：`LayoutEdge` 契约（`02` §10）不带端点 spanId，无法增量识别旧边，只能整体重建 —— 节点坐标计算本身仍是 O(受影响集合)
7. **bounds 只增不减**：不受影响节点天然落在 prev.bounds 内，只对受影响节点取最大（作为视口范围的安全上界）

`version` 仅在实际发生变更时 +1；纯函数零副作用，不修改 prev / graph。

### dirty 标记约定（写给 T5）

## 4. 决策点与偏离说明

1. **增量层内排序没有跑 4 轮交替扫描**，改用一次性「上游已落位节点 y 中心均值」排序（`layout.ts:296-309`）。理由：增量的硬约束是**未受影响节点逐字段不动**，而交替上扫会要求按下游重排上游层，牵动固定节点；层号升序处理保证约束边的上游（固定或已落位）必先就位，一次性重心即可。两条路径的层级结果已断言收敛（测试 `:252`），层内顺序允许有差。
2. **新节点排在同层固定节点下方**（`maxFixedY + Y_STRIDE` 起步，`layout.ts:311`）。任务卡未规定增量时同层新旧节点的相对位置，为杜绝同层重叠我选择固定节点优先靠上、新节点靠下，并加了「同层 y 互不重叠」断言（测试 `:199`）。
3. **边数组 O(E) 整体重建**：`LayoutEdge` 契约不带端点 spanId，增量无法识别哪条旧边失效。已在代码注释（`layout.ts:318-319`）说明：坐标计算仍是 O(受影响集合)，边重建是 O(E)。若审查认为 O(Δ) bullet 要求边也增量，需先修订 `02` §10 给 `LayoutEdge` 加端点标识 —— 现契约下这是最优解。
4. **兜底防御两处**（任务卡未要求，均为安全网）：(a) 图里有、prev 里没有的 span 自动并入受影响集合（防调用方漏标 dirty，测试 `:232`）；(b) prev 里有、图里没有的节点触发剔除重建（防 run.snapshot 清场后误用增量，测试 `:332`，结果为空布局 + version 自增）。两处都不改变正确调用路径的行为。
5. **无变更返回 prev 本身**（引用相等而非内容相等的新对象，`layout.ts:257`）：渲染层可用 `newLayout === prev` 零成本判断跳过重绘，比只比 version 更直接。version 语义同时保持「无变更不自增」。
6. **bounds 只增不减**（`layout.ts:322-331`）：增量模式下不重扫未受影响节点，直接以 prev.bounds 为基线对受影响节点取最大。语义是视口安全上界而非紧包围盒（图只会生长的应用场景下二者等价，剔除节点的防御路径除外）。
7. **空布局起始 version 约定**：`layoutGraph` 从 1 起（首个真实布局）；测试 helper `emptyLayout()` 用 0 起步模拟「从未布局过」，随事件流生长后 `version === dirty 调用次数`（测试 `:245`）。
