# 01 · 技术选型与目录结构

## 1. 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **React 18** | 见下方「选型修正说明」 |
| 构建 | **Vite 5** | 纯客户端工具，不需要 SSR；静态产物可直接部署成简历链接 |
| 语言 | TypeScript 5（strict） | — |
| 状态 | **Zustand 5** | 与 `DecisionCourt-new` 一致；轻量，不引入 Provider 嵌套 |
| 样式 | **Tailwind CSS 3** | 与 `DecisionCourt-new` 一致 |
| 渲染 | **Canvas 2D**（自研） | 见「渲染方式决策」 |
| 测试 | Vitest | core 层纯函数必须可单测 |
| 图布局 | **自研增量分层布局** | 技术亮点，禁止用库 |

### 选型修正说明：从 Vue 3 改为 React 18

初始建议是 Vue 3（基于 `gvknow-ui` 的技术栈延续性）。探查 `E:\Code\DecisionCourt-new` 后发现其前端已采用 **Next.js 14 + React 18 + Tailwind + Zustand**，据此改判为 React 18：

1. `DecisionCourt-new` 是当前主力项目且未来是本项目的真实事件源，技术栈一致可复用状态管理模式与组件习惯
2. Agent 前端生态（AG-UI、CopilotKit、LangGraph 前端）以 React 为主，Phase 2 接真实 Agent 运行时时可低成本复用社区成果
3. 求职面向的 Agent / AI 前端岗位，React 占比更高

**若后续确定主投 Vue 岗位，可切换为 Vue 3**：`src/core/` 与 `src/render/` 为零框架依赖层，迁移成本集中在 `src/ui/`（约 4 个组件）。

### 渲染方式决策：Canvas 2D，且从第一天就用

垂直切片只有 20 个节点，用 SVG + DOM 事件显然更快出效果。仍然选择直接 Canvas 2D：

1. 目标规模是 10000 span。若 T5 用 SVG、T7 再换 Canvas，等于渲染层整体重写
2. 节点均为矩形，命中测试就是 AABB 检测，不超过 30 行，并非高成本
3. 从第一天就建立「渲染层与 DOM 解耦」的架构，后续优化视口裁剪、脏矩形重绘都在正确的地方做

不选择 WebGL：10000 节点规模下 Canvas 2D + 视口裁剪已足够，WebGL 属于过度设计。

## 2. 依赖白名单（未登记者禁止安装）

```
运行时：  react  react-dom  zustand  clsx
开发期：  typescript  vite  @vitejs/plugin-react  @types/react  @types/react-dom
          vitest  @vitest/coverage-v8  tailwindcss  postcss  autoprefixer
```

`@vitest/coverage-v8`（2026-09-05 登记，T3 审查裁决 2）用于量化 `src/core/**` 测试覆盖率：

- 版本必须与 vitest 主版本对齐（vitest `2.1.9` → `^2.1.9`），否则报 provider 不匹配
- **只能**是 devDependencies，且 `src/` 下不得 import 它
- 覆盖率只考核 `src/core/**`；`src/render/` 靠压测，`src/ui/` 靠目视
- 提交时给完整 text reporter 输出（含未覆盖行号），不是只报一个总数
- 禁止为凑数字删断言、加无意义测试或加 `istanbul ignore`

**明令禁止的依赖及原因**：

| 禁止 | 原因 |
|---|---|
| `dagre` `elkjs` `d3-force` `cytoscape` | 图布局是本项目的核心技术亮点，且这些库都是全量重排，不支持增量 |
| `reactflow` `@xyflow/react` | 现成图组件会吃掉全部技术含量，且 DOM 渲染无法支撑 10000 节点 |
| `@ag-ui/*` | 协议解析层自研是面试加分项（"我按规范实现了，约 300 行"） |
| `d3`（整体） | 只需其中极少数工具函数，自己写，避免为几行代码拖入整个库 |
| `three.js` `pixi.js` | 过度设计 |
| `lodash` | 需要的函数自己实现，控制体积与可控性 |
| 任何 UI 组件库（antd / MUI / shadcn） | 调试工具界面自有风格，且避免依赖膨胀 |

## 4. 分层依赖规则（违反即退回重做）

```
ui/  ──→  store/  ──→  core/
  │          │
  └──────────┴──→  render/  ──→  core/types.ts
```

- `core/` **不得 import** `render/`、`store/`、`ui/`，不得 import 任何 React 相关内容
- `render/` **不得 import** `store/`、`ui/`，只依赖 `core/types.ts`
- `ui/` 只做状态绑定与事件转发，**不得承载任何业务逻辑**
- 箭头只能从左到右，禁止反向依赖

## 5. 代码风格

- 严格 TypeScript，`strict: true`，禁止 `any`（`unknown` + 类型收窄代替）
- 禁止 `@ts-ignore` / `@ts-expect-error`
- 函数优先纯函数，副作用集中在 `source/` 与 `store/`
- `core/` 下每个模块必须配 `.test.ts`，核心逻辑测试覆盖率目标 ≥80%
- 中文注释用于解释「为什么」，不解释「做了什么」
