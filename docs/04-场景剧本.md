# 04 · 场景剧本

剧本是**数据不是代码**：放在 `scenarios/*.json`，新增剧本不需要改任何代码。

## 1. 时间偏移约定

剧本里**不写绝对时间戳**，只写相对 run 开始时刻的偏移（毫秒），由 `src/core/source/scenario.ts` 在加载时加上 `runStartedAt` 转换成绝对时间。这样剧本可重复运行、可移植。

```ts
// 剧本中的形式
"timeOffset": { "createdAtMs": -7862400000 }

// 加载后转换成 DataEntity.time
{ createdAt: runStartedAt - 7862400000, observedAt: <事件实际发生时刻> }
```

- `createdAtMs`：数据**自身**的产生时刻相对 run 开始的偏移，**负数表示过期数据**
- `observedAtMs`：可选。省略时取事件实际发生时刻
- `delayMs`：相对上一个事件的延迟，用于模拟真实耗时

常用换算：1 天 = 86400000 ms；91 天 = 7862400000 ms；2 天 = 172800000 ms。

## 3. 这个剧本要证明什么

跑完后的因果边（由 `02` 第 4 节规则自动推导）：

```
s-retrieve --(e-resume-v1)--> s-score --(e-score)--> s-decide
```

在 UI 上点 `s-decide`（决策·拒绝）反向溯源，应当看到：

```
决策·拒绝 ←[评分 60] 评估 Agent ←[简历 v1 · 91 天前 ⚠] 检索 Agent
```

**对照组的意义**：`e-policy`（评分策略）同样是上下文，但只过期 2 天，标记为 `fresh` 正常显示。
这证明系统是在**真的计算新鲜度**，而不是把所有上下文一律标红。面试时这一点务必讲出来。

## 4. UI 呈现约定（对 `02` 第 10 节的补充）

图上的**节点是 span**，数据实体以**徽章**形式渲染在因果边的中点上：

- 徽章显示实体 `label`
- 新鲜度为 `stale` 的实体，徽章变红并显示天数（如「91 天」）
- 徽章可点击，点击后在右侧检查器展示该实体的 `payload`、`time`、`source`

这样既保持图结构简洁（节点数 = span 数，不翻倍），又让过期数据成为视觉焦点。
