# 05 · 部署步骤（GitHub Pages）

> 本文档面向项目所有者（用户本人）。执行者已备齐全部配置，**实际推送由用户完成**。
> 全程约 10 分钟，无任何服务器成本。

## 前置条件

- 本机已装 Git 与 Node 22+（开发环境已有）
- 一个 GitHub 账号

## 第 0 步 · 确认仓库名（影响 vite base）

[vite.config.ts](../vite.config.ts) 的 `base` 当前为 `/agent-trace/`，对应 Pages URL
`https://<用户名>.github.io/agent-trace/`。

- 仓库就叫 **agent-trace**：无需改动
- 想用别的名字：建仓库后把 `base` 改成 `/<你的仓库名>/`（注意首尾斜杠），否则构建产物引用 JS/CSS 会 404

## 第 1 步 · 建仓库

GitHub → New repository：

- Repository name：`agent-trace`（或你选的名字，回到第 0 步同步 base）
- Visibility：**Public**（简历用途；Private 仓库的 Pages 需要 Pro 订阅）
- 不要勾选任何初始化选项（README/.gitignore/license 都不要——本地已有内容）

## 第 2 步 · 推送

在项目根目录（`E:\Code\agent-trace`）执行：

```bash
git remote add origin https://github.com/<用户名>/agent-trace.git
git push -u origin main
```

> 本地若分支名是 master，先 `git branch -M main` 再推送——部署 workflow 监听 `main`。

## 第 3 步 · 开启 Pages（GitHub Actions 模式）

仓库页面 → **Settings → Pages**：

- Build and deployment → Source 选 **GitHub Actions**（不是 Deploy from a branch）

保存即可。push 到 main 会自动触发 [.github/workflows/deploy.yml](../.github/workflows/deploy.yml)：
安装依赖 → `npm run build` → 发布 dist。首次约 1-2 分钟，Actions 标签页可看进度。

完成后访问 `https://<用户名>.github.io/agent-trace/`。

## 第 4 步 · 验证部署

线上跑一遍与本地 preview 相同的演示路径：播放 stale-context → 进入时间旅行 →
拖到 step 5 → 分叉 → 切分支 → 推演重跑 → 决策对比行出现。

之后每次 `git push` 自动更新线上版本（main 分支）。

## 简历用法建议

- **线上演示链接**：`https://<用户名>.github.io/agent-trace/`（Pages URL）——放在简历项目条目的显著位置，点开即演示
- **仓库链接**：`https://github.com/<用户名>/agent-trace`——简历里与演示链接并列；面试官看代码、点演示两不误
- 两者搭配：一行演示链接（「在线体验」）+ 一行仓库链接（「源码」）；README 顶部同样放这两个入口

## 常见问题

| 现象 | 原因与修法 |
|---|---|
| 线上白屏、控制台 404 | `base` 与仓库名不一致——回第 0 步 |
| Actions 跑了但页面 404 | Settings → Pages 的 Source 没选 GitHub Actions |
| **Actions 一次都没跑过（Runs 列表为空）** | **`deploy.yml` 没提交上去**——`git status` 有未提交文件时 push 只推已提交内容。`git add -A && git commit && git push` 即可触发（2026-09-06 实测踩过：T9/T10 全部工作未提交，线上只有初始 commit） |
| 构建失败 Node 版本问题 | workflow 固定 Node 22；本地 `npm run build` 能过则 CI 也能过（依赖锁在 package-lock.json） |
