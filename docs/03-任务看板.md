#### 2-0：必修修补（**先做，再做本体**）

**B1 · `consumersIndex` 在 invert 后残留，导致索引单向膨胀**（阻塞）

- **机理**：`ingestSpan` 里 `consumersOf(graph, entityId).push(span.id)` 不记逆，而 `invert` 回滚 `span.set(prev: null)` 时只 `spans.delete()`，**索引里的 spanId 不会被移除**。索引是 `build.ts` 模块级 `WeakMap`，原图一直持有它，`consumersOf` 的惰性重建**永远不会触发**（惰性只在 `get(graph) === undefined` 时生效）

  ```
  applyEvent(span.start A 消费 E1)  →  index['E1'] = ['A']
  invert(span.set{A, prev: null})   →  spans.delete('A')；index['E1'] 仍是 ['A']
  applyEvent(span.start A 消费 E1)  →  index['E1'] = ['A', 'A']   ← 膨胀
  ```

- **后果**：每次"回滚 + 前进"循环累积一次。用户反复拖时间轴（**时间旅行最核心的交互**）时线性增长——10k span 拖 100 次，索引从 1 万涨到 100 万条。且 `ingestEntity` 遍历索引时 `addEdge` 被调用 N 次（幂等拦住边重复，功能仍正确，但每次付 O(出边数) 的 `some()` 扫描）
- **为什么测试没发现**：`snapshot()` 只比 `CausalGraph` 字段，索引不在图对象上；且压力测试是**单向回滚**，从不"回滚后再前进"
- **修复方向（设计裁决）**：**`invert` 时让索引整体失效，下次惰性重建**。不为缓存设计精确逆操作——它可从 `spans` 推导，"整体失效"才是缓存的正确语义；**不新增第五种 `InverseOp`**，§11.3 四类契约保持不变；惰性重建让"回滚后不重放"零成本
- **实现提示**：`consumersIndex` 现为 `build.ts` 模块私有，`journal.ts` 访问不到。建议抽 `src/core/graph/consumers-index.ts`（注意 `build.ts → journal.ts` 是 type-only import，抽取后仍无循环）。具体结构由执行者定
- **验收**：补「回滚 + 重放」**往返**测试——往返 N 次后断言索引不膨胀（需导出测试可见的查询入口，或经 `addEdge` 调用次数间接断言）
