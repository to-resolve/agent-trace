```md
# T{n} 审查结论

**结论**：通过 / 打回

## 一、红线检查
- [ ] 核心层零框架依赖
- [ ] 无白名单外依赖
- [ ] 无 any / @ts-ignore
- [ ] 未超出任务卡范围

## 二、契约一致性
与 `02-数据模型与事件协议.md` 逐字段比对结果。

## 三、问题清单
| 严重度 | 问题 | 位置 | 处理要求 |
|---|---|---|---|
| 阻塞 | | | |
| 建议 | | | |

## 四、设计层面的发现
实现过程中暴露出哪些设计问题，是否回头修订 01 / 02 文档。

## 五、对后续计划的影响
下一批任务卡的内容调整、新增或删除。
```

## 审查优先级

1. **红线** —— 违反直接打回，不进入后续评审
2. **契约一致性** —— 与 `02` 文档零偏差是硬要求
3. **设计是否走偏** —— 实现方式是否背离了技术亮点目标
4. **实现质量** —— 边界处理、错误处理、性能隐患
5. **代码风格** —— 不阻塞通过，但需记录

> 审查发现契约本身有问题时，**改文档而不是将就代码**。
