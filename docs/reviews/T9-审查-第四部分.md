## 2. 契约一致性（§11.6）

### 2.1 数据结构逐字段比对

`Branch`（id / baseEventIndex / events / note）与 `Timeline`（mainEvents / branches / activeBranchId）**与契约逐字段一致** ✅。`forkBranch` 签名一致 ✅。三条硬约束（不改主时间线 / 独立图实例零共享 / runId 派生）全部满足并有测试 ✅。

### 2.2 `forkBranch` / `createBranchSession` 职责分离 —— 采纳，判定为契约的合理细化而非偏离

契约只定义了 `forkBranch` 的签名（返回 `Branch`，不返回图）。执行者拆成「登记（纯数据）+ 按需建图」两层，理由充分：

- store 可先登记多条分支、UI 切换到哪条才建哪条的图——10k 规模下省内存
- fork 不依赖调用时的图状态（任何 seekTo 之后都能 fork）

**裁决 11（新增）**：采纳该分离。`createBranchSession` 补进 §11.6 的 API 清单（我修订文档，不劳执行者）。

### 2.3 `graph.runId = branch.id` 的一次显式赋值 —— 准了

任务卡原文「走 createGraph 工厂，不绕过 §5 构造约束」。实现里从零路径走 `createGraph(branch.id)` ✅；checkpoint 复用路径是 `cloneGraph` + 一次 runId 赋值。执行者在决策点 3 主动请求裁决，论证成立：

- §5 约束的是**结构写入**（spans/entities/edges/邻接表），runId 是图元数据
- clone 产图已是第二部分批准的既有模式（rebuildFromCheckpoint 同款）
- 赋值发生在构造路径内、有注释论证、有测试锁定（`expect(a.runId).not.toBe(b.runId)`）

**裁定**：合法。但为防止此口子被扩大解释，明确边界——**元数据赋值仅限构造路径内的 runId 一次性设置**，不得以此为先例对 spans/edges 等结构做「构造期直改」。已写入裁决 11。

### 2.4 主线 checkpoint 复用的正确性论证 —— 我独立验证成立

「前缀逐字一致 ⟹ 同一 applyEvent 规则 ⟹ 同一图 ⟹ 直接 clone」——这是 §4 唯一权威的必然推论，且「与独立重放逐字段相等」的测试直接背书了结论。✅

## 4. 问题清单

### 🔴 阻塞

### 🟡 必修（并入第五部分，不单独返工——两项都在第五部分改动面上）

**B4-1 · 分支会话的 checkpoint 覆盖缺口：不变量注释分叉 + 真实性能悬崖**

`ReplaySession` 的不变量注释声称「checkpoints 覆盖 [INTERVAL, total] 与终点；**journalBase 处必有检查点**」。分支会话**两者皆不满足**：own checkpoints 只从 base 之后打点（探针实测：组合流 860、journalBase=800，checkpoints=[860]；空分支时 checkpoints=[]）。

- **注释-实现分叉正是 B3 的温床形态**（HANDOFF 5.1 检查法：「注释在什么条件下与实现分叉？那条件被测试覆盖了吗？」——分支会话就是那个未覆盖的分叉点）
- **功能上当前正确**（回退低于首个 own checkpoint 时从零重放，结果对），但**性能上是悬崖**：10k 流上 fork 在 8000 处、拖回 7990 → 从零重放 ~8000 事件 ≈ 秒级到十秒级（对照：主线同样操作走 checkpoint 只重放 ≤200 步）。**「拖分支时间轴」恰是第五部分 UI 的核心交互**

**修法（推荐 ①）**：
- ① `createBranchSession` 把主线 ≤ baseEventIndex 的 checkpoints **共享引用**并入分支 checkpoints（Checkpoint 只读、使用时 clone，共享安全；无内存拷贝成本）——同时修复不变量与性能。**⚠️ 陷阱先说清**：`rebuildFromCheckpoint` 从主线 checkpoint clone 出的图带主线 runId，必须补一行 `graph.runId = session.runId` 归一（主线会话该行是 no-op，分支会话修正元数据——与 createBranchSession 同款模式）
- ② 只修注释、明确分支会话的覆盖语义——不解决性能悬崖，**不推荐**

**B4-2 · 分支事件区间的 invert 回退无测试**

branch.test.ts 的时间旅行测试用空分支（journalBase === applied，无区间可回退）。B3 的原触发形态（journalBase < applied + 区间内部回退）在分支会话上零覆盖——我的探针已验证当前实现正确，**把它转成正式测试**（含前提断言 `journalBase < applied` + 不变量断言 + 与独立重放逐字段相等）。探针代码在审查记录 §0.1，可直接取用。
