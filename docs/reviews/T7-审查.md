## 2. 通过的部分（核心成果扎实）

**① traverse 迭代化（query.ts）**
逐点比对了递归版语义，四点全部对齐：前序访问、`edges` 按进入顺序收集、`onPath` 命中设 `hasCycle` 但**当条边照常入集**、菱形汇合（A→B→D、A→C→D）直接弹回不算环。`onPath.delete` 的时机正确——放在该节点邻接边全部处理完之后，而非进入时。

**② 增量布局的环安全论证（layout.ts 文件头）**
「环必然整体落在 affected 内或整体在外，因此『不受影响 → 受影响』的入边不可能是回边」——论证成立。依据是 `affected = dirty ∪ 新节点 ∪ 沿出边的下游闭包`，环上任一节点 dirty 时沿出边可达整条环。

**③ 边级增量的完备性**
一条边要么来自 `prev.edges`（两端均不 affected，复用），要么来自 `affectedEdges`（至少一端 affected，重建）。两个集合**互斥且并集完备**，无丢失、无重复。新增边必挂 affected 端点的前提（`ingestSpan` 挂新 span、`ingestEntity` 挂 dirty 的 `producedBy`）与文件头调用约定自洽。

**④ 视口裁剪（culling.ts + renderer.ts）**
- DPR 逆变换正确：`setTransform(dpr,...)` 后用 **CSS 像素**做 `world = (css - offset) / scale`，与 Canvas 位图尺寸区分清楚，没有混用
- 边是直线段，端点 AABB **精确**，不存在曲线漏画的情形
- 闭区间判定与 `hit-test` 同语义

**⑤ 关键断言是真验证**
`culling.test.ts` 的「10k 节点与 200 节点在相同视口下 stub ctx 绘制调用数完全一致」——这个断言**真的能证伪**。若裁剪失效（比如忘记接入 `cullScene`），10k 的 fills 会是 200 的 50 倍，断言立刻红。这不是走过场的测试。

**⑥ 徽章平铺几何**
绘制 / 命中 / 裁剪 / 包围盒读同一份字段，「画在哪就点哪」。T6 审查提的建议条（徽章 rect 未命中时静默返回 `{0,0}`）**在结构上消灭**，不再依赖防御分支。

### B3 · 压测数字不可复现 —— 验收线是环境相关的

**两次独立复现（我这边高度稳定）**：

| 指标 | 提交材料（Node 24.18.1） | 第 1 次实测 | 第 2 次实测 | 验收线 |
|---|---|---|---|---|
| M2 updateLayout p50 | 0.215ms | 0.244ms | 0.236ms | — |
| **M2 updateLayout p95** | **1.567ms** | **2.455ms** | **2.317ms** | **< 2ms ❌** |
| M4 buildScene p95 | 6.565ms | 9.599ms | 9.197ms | 无硬线 |
| M5 完整回放 | 69.4s | 104.1s | 100.4s | — |
| M3 traceUpstream p95 | 6.756ms | 8.167ms | 8.283ms | < 10ms ✅ |

**约 50% 的系统性偏差，不是波动**（两次实测一致性很好，且 CPU 相同：AMD Ryzen 7 6800H）。

**根因已定位**：Node **v22.22.2（V8 12.4）** vs 执行者声明的 **v24.18.1（V8 13.6）**。跨 V8 大版本，Map/Set 密集 + 大量短命对象分配的代码出现 50% 差异完全可能。**不是造假，是环境差异。**

**但这暴露了更严重的问题：「p95 < 2ms」这条验收线是环境的函数，不是代码的客观属性。** 在 Node 24 下达标、Node 22 下不达标——同一份代码，两种结论。指挥者与执行者用各自 PATH 里的 Node 跑同一个 bench，得出相反判断，这在本轮真实发生了。

**附带发现的方法学缺陷**（bench 文件本身）：

1. **无 JIT 预热**：模块级一次性执行，从第一个事件就开始采样。前几千次调用处于基线编译/解释执行阶段
2. **样本混合了两个不同总体**：27717 个样本里，前段是「小图」（图从 0 增长到 10007）、后段是「满图」。`p50` 因此被小图阶段系统性稀释
3. **无多轮取中位数**：单次运行，无法剔除 GC 暂停与 OS 调度的随机影响
4. **测量开销占比过高**：每个事件 6 次 `performance.now()`，在 M2 的 0.24ms 绝对值上占比可观
5. **无环境指纹输出**：bench 输出里没有 Node / V8 版本、CPU、平台——这正是本次无法自查的原因

**裁决（裁决 6 · 压测方法学）**：

| # | 要求 |
|---|---|
| 1 | bench 输出必须带**环境指纹表头**：Node 版本、V8 版本、CPU、平台、负载状态 |
| 2 | 加**预热**（丢弃前 10% 轮次）+ **多轮取中位数**（≥ 3 轮） |
| 3 | 明确采样口径：要么只测「满图状态下的单事件成本」（固定图规模，反复触发），要么明确声明是「回放全程分布」并只报 p95/p99（p50 无意义） |
| 4 | 改用批量计时（外层计时求差）降低计时开销占比，或明确扣除基线 |
| 5 | **验收标准改为「同环境下相对基线的改善率」**（如：M2 p95 相对 T7 优化前基线降低 ≥ 50%），绝对毫秒数仅作为标注环境的参考值 |
| 6 | `package.json` 加 `engines` 声明推荐 Node 版本，避免再次出现「两个环境、相反结论」 |

**关于简历叙事**：对外讲**浏览器实测数字**（10k 节点、120 帧平移缩放、帧间隔 p50 6.9ms / p95 7.0ms、≈137fps）。这才是用户可感知的真实指标，且与 Node 版本无关。Node 压测数字只用于开发期性能回归，写简历时不要引用。

## 4. 建议项（不阻塞，按优先级）

### S1 · `computeLayering` 递归深度存在理论爆栈路径

当前调用约定下实测递归深度只有 1–2，**安全，不要求改**（符合卡面「不爆栈则不改」）。

但可构造反例：若 `affected` 集合中节点按**逆拓扑序**入集，则 `visit` 沿入边的未 memo 链长可达 O(V)。

具体构造：`A → B`，同时 `A → C₁ → C₂ → … → C_k → B`。当 `B` 先于 C 链入 `affected`（取决于 `outgoing` 的边顺序与 DFS pop 顺序）时，`visit(B)` → `visit(C_k)` → … → `visit(C₁)`，深度 k+1。synth 的三种拓扑都不会产生这种形态，真实 Agent trace 里概率也低。

**要求**：把「递归深度上界 = affected 子图内沿入边的未 memo 链长」这一约束写进 `layout.ts` 文件头注释。当前注释只论证了**环安全**，没有论证**栈深**——两者是不同的风险，后者目前只有实测背书，没有文字约定。

### S2 · `LayoutEdge.state` 与 Layout 的耦合（架构建议，B5 评估）

`traceStore` 里 `scene.layout` 是 `buildScene` 的输出，**既是几何布局又承载视觉态**。本次的修复（null 时显式归零）是**补丁式**的——它依赖「每个设置 state 的路径都记得归零」这个约定。

更结构性的方案：把视觉态移出 `Layout`，由 `Scene` 携带 `Set<edgeKey>`（复用已有的 `edgeKey` 三元组标识）。这样：

- `Layout` 退化为纯几何，可安全缓存、复用、序列化（Phase 1 的 `ReplaySource` 需要用）
- `updateLayout` 不再需要「复用时归零 state」的隐式契约
- `applyEdgeStates` 的 null 分支自然消失（`Scene` 重建时 states 为 null）

代价是改动 `docs/02` §10 契约 + `layout.ts` + `scene.ts` + store。**不阻塞本轮，进 B5 评估**——但当 Phase 1 的回放/快照落地时，Layout 的纯几何化会变成硬需求。

执行者的判断正确：M4 p95 6.6ms（Node 24）**远低于 16.7ms 帧预算，不构成交互瓶颈**；它限制的是**回放吞吐**，根因是 `buildScene` 每事件全量重建 `nodeVisuals` / `badges` 的 O(N+E) 设计。

## 5. 值得肯定的地方

- **如实报告负数据**：边级增量第一版用字符串三元组键，使 M2 p95 从 4.05 **恶化到 5.20ms**；`makeBadge` 中间对象 + 嵌套 rect 双分配使 M4 p50 **+0.7ms**。两处「越优化越慢」都被复测数据当场抓获并纠正，且完整写在提交材料第 1 节。这正是「先测量再修」流程的价值——**预防性直觉不可信**
- **主动修复卡面外的 bug**：`applyEdgeStates` 状态残留（选中→取消后边永久高亮）不在任务卡范围内，是重构时发现的。且准确定位了漏网原因（T5 六步验收没覆盖「取消」路径）
- **确定性合成器设计正确**：`synth.ts` 同参数必产同流，让两次压测可比。这是压测基础设施的关键决策，执行者做对了（即便本次栽在了计时环境上）
- **深链爆栈守卫做成常驻测试**：不只写进提交材料，而是每次 `npm test` 都跑——任何人把 `traverse` 改回递归会立刻红
