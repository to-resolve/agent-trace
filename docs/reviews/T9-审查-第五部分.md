## 2. 5-1 store 集成核验

- **会话生命周期**：模块级 `session`/`branchSessions` 不进 React 状态（大对象、不可序列化），store 只暴露派生视图——分层正确。`startRun` 丢弃全部时间旅行状态（会话/分支/终态基准/事件流归零），无残留路径。
- **`mainFinalGraph` 终态基准**（决策点 2）：解决了「session 被 seek 回退后主线对比拿到过去数据」的真实陷阱。别名安全性核过：enterTimeline 仅在 done/cancelled 后可入，迟到事件被 `state.graph !== graph` 恒等检查丢弃，live 图此后无任何写入点——引用捕获是安全的。
- **`injectBranchEvents` 批量 API + 重建时机收敛一处**（决策点 1）：与裁决 11 条 1 的 fork/建图分离自洽；逐事件重建 10 次组合流的浪费被避免。
- **dirtyOf 统一**（第四部分审查建议 1 落实）：checkpoint.ts 导出唯一实现，branch.ts / traceStore.ts 改引；bench ×3 保持原样的处理与审查原文（「bench 可后置」）一致。

## 5. 发现与建议（均非阻塞）

### 建议 1 · 分支视图下「在此分叉」按钮的语义错位（低危，B7 顺手修）

`store.fork` 注释写明「分支会话场景先切回主线再 fork 是 UI 约定」，但 TimelineBar 的分叉按钮在分支视图下**并未禁用**。用户在分支视图（位置 860）点分叉，实际 fork 的是**主线主会话的当前位置**（可能是 15）——所见与所得静默不一致。修法一行：分支视图下禁用该按钮或加提示。演示主路径（主线分叉→切分支→注入）不受影响，不定阻塞。

### 建议 2 · 重复注入已探针验证幂等（记录，无需动作）

指挥者探针（已删）：同一反事实序列注入两次，分支图 edges/spans/entities 与注入一次**完全相同**（2/4/5），决策 payload 正确。span.set 替换语义 + consumersOf 惰性重建使重复事件序列幂等。**这个形态没有踩雷，但属侥幸而非设计**——建议在 B7 给 `injectStaleResumeRerun` 加一行幂等守卫（`branch.events.length > 0` 时 no-op 或先清空），把侥幸变成契约。
