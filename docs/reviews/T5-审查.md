### 必修项 1：下标对齐耦合

`applyEdgeStates` 假设「`graph.edges` 按顺序过滤掉端点未落图的边后，与 `layout.edges` 一一对应」，`buildBadges` 的边徽章锚点（`edgeIndex`）同样依赖这个对应。今天成立——两处过滤谓词与遍历顺序完全一致；但这个不变量**没有被任何类型或断言保护**，散落在两个文件里。一旦任何一方改了过滤条件（如渲染层决定不画回边），高亮会静默落错边。

`02` §10 已修订（`LayoutEdge` 增加 `fromSpanId` / `toSpanId`），T6 中：`buildEdges` 写入端点标识，store 与 `BadgeAnchor` 的 edge 变体改用标识定位，删除全部下标推算。

### 必修项 2：业务代码 import 剧本 JSON

T2 审查建议条原文：「禁止 `src/` 业务代码直接 import 剧本 JSON，否则所有剧本都会打进产物」。当时只有测试在 import，现在 `traceStore.ts:13` 把 `stale-context.json` 编进了 bundle。当前单剧本危害有限，但 Phase 1 要加三个剧本，再往后是用户导入的 trace——必须现在切到正确形态。

**T6 要求**：改用 Vite 原生 `import.meta.glob` 懒加载 `scenarios/*.json`（零新依赖），剧本注册表随文件自动生长——这同时兑现 `04` §5「新增剧本只需加 JSON 文件」的承诺，连 `listScenarios` 的手工登记都省了。
